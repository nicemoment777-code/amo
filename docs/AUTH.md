# Вход в личный кабинет

Основной адрес: `https://snowbrick.ru/login`. На сайте используется отдельная страница с полями «Логин» и «Пароль», а после входа — кнопка «Выйти». HTTP Basic Auth в актуальном сценарии развёртывания отключён.

При первой установке создаётся пользователь `admin` и случайный пароль. Повторное развёртывание сохраняет реквизиты из `/root/amo-dashboard-credentials.json`; при обновлении старой установки возможен перенос из `/root/amo-dashboard-credentials.txt`. Оба файла доступны только root, режим `0600`. Не выводить их содержимое в GitHub Actions, публичные логи или документацию. Удаление этих файлов приведёт к созданию новых реквизитов при следующем развёртывании.

Приложение получает только имя пользователя и salted scrypt-хеш пароля из `/etc/amo.env`. Обязательные переменные для публичного сервера: `NODE_ENV=production`, `APP_ORIGIN=https://snowbrick.ru`, `DASHBOARD_USERNAME`, `DASHBOARD_PASSWORD_HASH`. Неполная конфигурация останавливает сервер. В локальном режиме без этих переменных сохраняется доступ без входа только через loopback.

Сессия действует 12 часов. Cookie имеет `Secure`, `HttpOnly`, `SameSite=Lax`; токены сессий хранятся в памяти сервера в виде хешей. Выход немедленно отзывает текущую сессию, повторный вход меняет её токен. Перезапуск службы требует войти заново. Неверные попытки входа ограничены по IP и общим лимитом; POST-запросы проверяют точный Origin сайта.

Nginx передаёт приложение на `127.0.0.1:3080`, сохраняет настоящий заголовок Origin и перезаписывает X-Real-IP. Заказы и управляющие API требуют сессии. Без неё `/` перенаправляет на `/login`, а `/api/state` возвращает 401 **без** `WWW-Authenticate`, поэтому браузер не открывает своё окно авторизации. `/healthz` возвращает только признак работы сервера.

Приём вебхуков СДЭК использует свой секретный путь и не требует пользовательской сессии. Пароль личного кабинета не связан с паролями SSH, DNS или ключами СДЭК.

Проверки: `node --test` включает HTTP-тесты входа, выхода, истечения и смены сессии, ограничений попыток, защиты API и Origin, а также независимой авторизации вебхуков. `ops/check-deployment.mjs` на VPS проверяет настоящий HTTPS, вход, импорт известных накладных, выход и отказ по отозванной сессии. Скрипт выводит только результаты и количества заказов.

Это один аккаунт владельца. Регистрация, несколько пользователей и восстановление пароля по электронной почте не реализованы.
