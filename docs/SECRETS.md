# Ключи и пароли

Значения находятся в [Settings → Secrets and variables → Actions](https://github.com/nicemoment777-code/amo/settings/secrets/actions). В файлах репозитория хранятся только имена и назначение.

| Repository secret | Что хранит | Как использовать |
| --- | --- | --- |
| `AMO_ACCOUNT_ID` | Идентификатор клиента API СДЭК | Передать как `CDEK_CLIENT_ID` или `AMO_ACCOUNT_ID` |
| `AMO_PASSWORD` | Секрет клиента API СДЭК | Передать как `CDEK_CLIENT_SECRET` или `AMO_PASSWORD` |
| `AMO_CREDENTIALS_UPDATED_AT` | Дата обновления исходных реквизитов | Справочная информация |
| `VPS_SSH_HOST` | IP нового сервера Рег.облака | SSH host: `194.58.102.218` |
| `VPS_SSH_USER` | Пользователь сервера | SSH user |
| `VPS_SSH_PASSWORD` | Пароль нового VPS | Вход root успешно проверен 17.09.2026 |
| `VPS_SSH_KNOWN_HOSTS` | Зафиксированный ED25519 host key | Проверка ключа сервера при SSH из Actions |
| `REG_VPS_DOMAIN` | `snowbrick.ru` | Основной домен нового VPS; сохранён после проверки DNS |
| `LEGACY_CLOUD4BOX_SSH_HOST` | IP предыдущего VPS | Архив и ручное восстановление старого сервера |
| `LEGACY_CLOUD4BOX_SSH_PASSWORD` | Прежний пароль Cloud4box | Не использовать для нового VPS |
| `VPS_DOMAIN` | Старый домен Cloud4box | Только прежний сервер |
| `VPS_CONSOLE_URL` | Старая VNC-ссылка Contell | Только прежний сервер; ссылка может истечь |
| `CDEK_ORDER_NUMBERS` | 20 известных номеров накладных | Повторная загрузка исходной выборки через API |

Имена `AMO_*` исторические: это ключи СДЭК, а не ключи amoCRM. Создавать дубликаты под другими именами не требуется.

`REG_VPS_DOMAIN` содержит только `snowbrick.ru`, без протокола и пути. Домен и `www` уже направлены на новый VPS. DNS-реквизиты из письма дважды отклонены отдельной хостинговой панелью и не сохранены как действующие. Текущая зона обслуживается бесплатными `ns1.reg.ru` / `ns2.reg.ru`, и владелец уже изменил записи через личный кабинет Рег.ру; доступ к хостинговой DNS-панели для этого не нужен.

## Передача в GitHub Actions

Секрет нужно явно передать только тому шагу, которому он требуется:

```yaml
env:
  CDEK_CLIENT_ID: ${{ secrets.AMO_ACCOUNT_ID }}
  CDEK_CLIENT_SECRET: ${{ secrets.AMO_PASSWORD }}
```

Обычная проверка `node --test` работает без секретов. GitHub скрывает значения после сохранения: через интерфейс можно заменить секрет, но нельзя прочитать его обратно. Храните исходные значения также в личном менеджере паролей. Не делайте workflow для печати или выгрузки секретов.

## Сервер и локальный запуск

Локально скопируйте `.env.example` в `.env` и внесите значения. На VPS будущая служба должна получать переменные из отдельного файла с ограниченным доступом, например `/etc/amo.env`, который не входит в каталог Git. У приложения должны быть права на запись `data/`.

На новом VPS `CDEK_WEBHOOK_SECRET` пока не настроен. На прежнем сервере он уже создавался при облачном развёртывании. При переносе проверить существующие подписки СДЭК и выбрать порядок переключения. Не включать полный секретный URL в журналы прокси.

Приватный SSH-ключ для автоматического развёртывания пока не создан; используется проверенный пароль. Публичный ключ самого сервера зафиксирован в `VPS_SSH_KNOWN_HOSTS` и сверён внутри авторизованной SSH-сессии. Это не приватный ключ пользователя. После настройки отдельного пользователя развёртывания можно перейти на вход по ключу; проверку host key не отключать.

## Codex в браузере

Actions Secrets, Codespaces Secrets и секреты среды Codex — разные хранилища. Секреты Actions не появляются в облачной задаче автоматически. Подробности и рабочий порядок — [CLOUD.md](CLOUD.md).
