# Подключение amoCRM

Аккаунт: `snegostroy.amocrm.ru`. Эта интеграция отделена от ключей СДЭК `AMO_ACCOUNT_ID` / `AMO_PASSWORD`.

После установки актуального кода и конфигурации Nginx:

1. В amoMarket создайте интеграцию «Codex — Снегострой». Выберите только «Доступ к данным аккаунта»; остальные разрешения и опции оставьте выключенными.
2. Ссылка для перенаправления: `https://snowbrick.ru/integrations/amocrm/callback`. Хук отключения не задан. Сохраните интеграцию.
3. Войдите на `https://snowbrick.ru/login`, затем откройте `https://snowbrick.ru/integrations/amocrm`.
4. Введите ID и секретный ключ из настроек интеграции непосредственно в защищённую форму сайта. Не отправляйте их в чат или GitHub. Сохранение новых ключей сбрасывает прежние токены подключения.
5. Нажмите «Разрешить доступ в amoCRM», выберите нужный аккаунт и подтвердите доступ. Должна сохраниться та же сессия snowbrick.ru; после перезапуска службы или истечения сессии войдите и начните заново.
6. Нажмите «Проверить подключение». Проверка читает только параметры аккаунта, не меняет сделки и задачи.

Страница настраивает OAuth-доступ сервера. Инструменты MCP для работы Codex со сделками, контактами и задачами пока не реализованы; успешная авторизация сама по себе их не добавляет.

## Хранение и защита

ID, ключ и токены сохраняются атомарно в `data/amocrm.json`, на VPS — `/var/lib/amo/amocrm.json`, режим `0600`, владелец — пользователь службы `amo`. Файл находится вне каталога релиза и сохраняется при deploy. Резервные копии этого файла должны храниться как секреты. Пароль amoCRM приложению не нужен.

Публичный callback без параметров возвращает только сообщение о готовности адреса. Обработка кода требует действующей сессии, одноразового state со сроком 10 минут и точного аккаунта `snegostroy.amocrm.ru`. Произвольные домены из callback не используются для запросов. Параметры и ответы провайдера не возвращаются в ошибках. Callback отключён в access/error log Nginx, ответы имеют `no-store` и `no-referrer`.

Обновление токенов выполняется при проверке подключения и фоновым таймером раз в минуту, когда до истечения осталось не более минуты. При фоновой ошибке повтор откладывается на 15 минут. Обмены и сохранения сериализованы, чтобы параллельные запросы не затёрли обновлённый refresh token. При отзыве доступа повторите авторизацию.

Тесты: `node --test`. OAuth и API в тестах заменены mock-ответами; реальные запросы не выполняются.

Документация провайдера: https://www.amocrm.ru/developers/content/oauth/step-by-step
