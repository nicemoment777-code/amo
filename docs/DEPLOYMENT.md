## Проверка SSH

Из Git Bash или Linux:

```bash
ssh -v -o ConnectTimeout=15 root@185.77.219.91
```

Пароль вводится в приглашении SSH, не в командной строке. Перед первым доверием ключу сравните его отпечаток с полученным через консоль провайдера.

Если соединение снова зависает на SSH-приветствии, войдите в консоль VPS через панель провайдера. После входа выполните:

```bash
cat /etc/os-release
systemctl status ssh.service ssh.socket --no-pager
ss -lntp
sudo /usr/sbin/sshd -t
sudo journalctl -u ssh.service -n 80 --no-pager
sudo ufw status verbose
sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

Если OpenSSH Server отсутствует, установить из репозитория Ubuntu:

```bash
sudo apt update
sudo apt install openssh-server
sudo /usr/sbin/sshd -t
sudo systemctl enable --now ssh.service
```

Если UFW включён и порт 22 закрыт, разрешить `sudo ufw allow 22/tcp`. Отдельно проверить сетевой firewall в панели провайдера. Не отключать весь firewall. Учитывать, что на Ubuntu может использоваться активация через `ssh.socket`; сначала изучить вывод диагностики.

## Домен и HTTPS

1. Проверить A-запись `861659.cloud4box.ru`: она должна указывать на `185.77.219.91`. Если используете свой домен — создать такую же A-запись для выбранного имени. Не добавлять AAAA без настроенного IPv6.
2. Проверить, что выбранное имя можно использовать для приложения и получения TLS-сертификата. Выданное провайдером имя ещё не проверено на выпуск сертификата.
3. Настроить reverse proxy (Caddy или Nginx), доступные входящие TCP 80/443 и сертификат доверенного центра. Платный сертификат для этой задачи не обязателен.
4. Node.js оставить на `127.0.0.1:3080`. Порт 3080 наружу не открывать.
5. Публично сначала направить только `POST /webhooks/cdek/<секрет>` на Node.js. Все остальные внешние пути закрыть, пока не готов вход пользователей. Не записывать секретный путь в access log.

Это порядок будущей настройки, а не применённая конфигурация.

## Приложение

Установить Node.js 24 из официального источника, проверить `node --version`, клонировать репозиторий в постоянный каталог сервера и выполнить `node --test`. Внешних npm-зависимостей нет. Запускать `server.mjs` как службу systemd от отдельного пользователя с переменными из `/etc/amo.env`; дать этому пользователю запись в каталог `data/`. Настроить автозапуск и резервные копии данных.

До публикации интерфейса его можно открыть по SSH-туннелю:

```bash
ssh -N -L 3080:127.0.0.1:3080 root@185.77.219.91
```

Затем открыть `http://127.0.0.1:3080`. Локальный экземпляр на том же порту должен быть остановлен. Постоянный браузерный доступ через домен потребует входа пользователей и изменения допустимых Host/Origin в `server.mjs`.

## СДЭК

После проверки публичного HTTPS endpoint задать `CDEK_WEBHOOK_SECRET`, проверить текущие подписки и зарегистрировать `ORDER_STATUS` через официальный API. Вебхук даёт номер новой накладной; подробности приложение читает из API с ключами клиента. Исторический архив вебхуками не восстанавливается.

После настройки проверить: автозапуск после перезагрузки, HTTPS, закрытость интерфейса без входа, приём события, появление номера в очереди и обновление заказа. До этих проверок развёртывание не считать завершённым.
