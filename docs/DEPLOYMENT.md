
Эта команда рассчитана на уже сохранённый ключ сервера. На новом компьютере сначала добавьте доверенную строку из `VPS_SSH_KNOWN_HOSTS` в файл `~/.ssh/known_hosts`. Пароль вводится в приглашении SSH и хранится в `VPS_SSH_PASSWORD`.

```text
SHA256:CcpNtAbdlRzJiL6Bj7QXXCTCRM/8YTV2kuiYhYWjYxU
```

Ключ получен при первом подключении и совпал с ключом из авторизованной сессии. В Actions используется сохранённая строка known_hosts; повторное получение произвольного ключа из сети при каждом запуске не требуется. Для независимой проверки сравните отпечаток через консоль провайдера.

## DNS

Домен приложения — **snowbrick.ru**. Пользователь изменил записи в личном кабинете Рег.ру 17.09.2026. Для домена используются бесплатные DNS-серверы `ns1.reg.ru` и `ns2.reg.ru`.

| Тип | Имя | Целевое значение |
| --- | --- | --- |
| A | `@` (`snowbrick.ru`) | `194.58.102.218` |
| A | `www` (`www.snowbrick.ru`) | `194.58.102.218` |

Обе записи проверены 17.09.2026 в 21:10–21:11 МСК через DNS-over-HTTPS Google и Cloudflare: новый IP получен для обоих имён. Google вернул TTL 21600 секунд, Cloudflare — 86400 секунд. Запрос AAAA для основного домена через Google не вернул IPv6-адреса. Обычные локальные DNS-запросы в тот же момент показывали старый IP `194.58.112.174` с TTL 86400; это расхождение не отменяет внешнюю проверку, но означает, что не все пути разрешения имён уже показывают новое значение.

Для workflow в GitHub Secrets сохранено `REG_VPS_DOMAIN=snowbrick.ru`. Основной будущий URL — `https://snowbrick.ru/`. Запись `www` тоже направлена на VPS, но текущий скрипт развёртывания получает один домен: сертификат и Nginx для `www` нужно настроить отдельно, например с перенаправлением на основной адрес.

Отдельная панель из письма VPS — https://dnsadmin.hosting.reg.ru/manager/ispmgr — и её NS `ns5.hosting.reg.ru`, `ns6.hosting.reg.ru` не используются для этой зоны. Ранее она отклонила присланные данные; её пароль не нужен для текущей настройки на `ns1.reg.ru` / `ns2.reg.ru`.

Домен `861659.cloud4box.ru` и секреты `VPS_DOMAIN`, `VPS_CONSOLE_URL` относятся к старому провайдеру. Не применять их к новому серверу.

## Когда появится сайт

По [справке Рег.ру](https://help.reg.ru/support/dns-servery-i-nastroyka-zony/nastroyka-resursnykh-zapisey-dns/nastroyka-resursnykh-zapisey-v-lichnom-kabinete) публикация изменений ресурсных записей обычно занимает 15 минут — 1 час. В этой проверке Google и Cloudflare уже показывают новые записи. При прежнем TTL 86400 старые кэши могут сохранять адрес до суток с момента его кэширования.

Обновление DNS само по себе не устанавливает приложение. На момент проверки прямой HTTP-запрос к новому IP с Host `snowbrick.ru` завершился пустым ответом, HTTPS — ошибкой TLS-рукопожатия. Ещё нужно выполнить развёртывание, выпустить сертификат и проверить защищённый вход. Срок появления рабочего сайта зависит от выполнения этих шагов, а не только от ожидания DNS.

## Развёртывание

В репозитории есть `ops/provision-server.sh` и ручной workflow `Deploy production`. Они были созданы для предыдущего VPS; перед переносом проверить существующие подписки СДЭК и нужные данные. Workflow останавливается, если новый домен не указан или его IPv4-адрес отличается от целевого VPS.

Сценарий устанавливает Node.js, Nginx и HTTPS, создаёт службу `amo.service`, хранит данные в `/var/lib/amo` и переменные в `/etc/amo.env`. Node.js остаётся на `127.0.0.1:3080`; внешний доступ к панели защищается Basic Auth, webhook имеет отдельный секретный путь без access log. Порт 3080 наружу не открывать.

Старый сервер не выключен и его webhook не удалён. При переносе не создавать повторяющиеся подписки бесконтрольно; сначала проверить список в СДЭК. Завершить перенос можно только после проверки HTTPS, авторизации, данных и обработки нового webhook.

Команды проверки после будущего развёртывания:

```bash
systemctl is-active amo.service nginx.service
systemctl is-enabled amo.service
curl --fail --silent http://127.0.0.1:3080/api/state -o /dev/null
```

Ответы с заказами не выводить в публичные журналы. Сведения о предыдущем сервере сохранены в [LEGACY-CLOUD4BOX.md](LEGACY-CLOUD4BOX.md).
