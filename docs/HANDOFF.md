## Вход и секреты

Логин владельца — `admin`. Случайный пароль хранится в `/root/amo-dashboard-credentials.json` и `.txt` (0600), а его резервная копия — в GitHub Secrets `DASHBOARD_PASSWORD`; логин — `DASHBOARD_USERNAME`. Значения паролей в репозиторий не входят. В окружении приложения хранится только salted scrypt-хеш. Сценарий развёртывания сохраняет существующий пароль; GitHub Secrets с реквизитами кабинета автоматически его не переопределяют. Подробности: [AUTH.md](AUTH.md).

Сессии действуют 12 часов и хранятся в памяти. Перезапуск службы требует войти заново. В интерфейсе есть кнопка выхода. Неверные попытки ограничены, POST-запросы проверяют Origin. Basic Auth удалён из актуальной конфигурации Nginx. Регистрация и восстановление по email не реализованы: сейчас один аккаунт владельца.

`VPS_SSH_HOST`, `VPS_SSH_PASSWORD`, `VPS_SSH_USER` относятся к новому VPS; `VPS_SSH_KNOWN_HOSTS` содержит зафиксированный ED25519 host key. SSH успешно проверен из Git Bash и GitHub Actions. `REG_VPS_DOMAIN=snowbrick.ru`.

Старые SSH-реквизиты отдельно хранятся в `LEGACY_CLOUD4BOX_SSH_HOST` и `LEGACY_CLOUD4BOX_SSH_PASSWORD`. `VPS_DOMAIN` и `VPS_CONSOLE_URL` относятся только к старому Cloud4box.

## Заказы и СДЭК

На новом сервере загружены 20 известных заказов через API, ошибок синхронизации — 0. С исходного компьютера по SSH перенесены и объединены с актуальными API-данными все 20 `cabinetSnapshot`, чтобы сохранить историю кабинета, состав, цвет и количество. Повторная синхронизация сохранила 20 снимков. Данные находятся в `/var/lib/amo`; локальная база осталась на компьютере.

Резервная копия серверной базы перед объединением: `/root/amo-orders-before-snapshot-20260917.json`; исходный перенос: `/root/amo-local-orders.json`. Эти файлы доступны только root, не включать их в Git или публичные artifacts.

Известные номера обновляются при запуске и каждые 15 минут, очередь сохраняется, неудачные запросы повторяются. Ключи СДЭК — `AMO_ACCOUNT_ID` и `AMO_PASSWORD`; исходная выборка номеров — `CDEK_ORDER_NUMBERS`.

Подписка `ORDER_STATUS` для `snowbrick.ru` создана и подтверждена повторным `GET /v2/webhooks`. В списке также остаётся прежняя подписка `861659.cloud4box.ru`; она не удалялась. Получение нового **реального** события от СДЭК после развёртывания ещё не подтверждено. Вебхук использует отдельный секретный путь, не требует входа пользователя и не логируется Nginx. Секрет хранится в `/etc/amo.env` и сохраняется при обновлении приложения.

Общего метода перечисления всего исторического архива в используемом API нет. Эти 20 заказов — известная выборка, полнота архива не подтверждена. Вебхуки позволяют узнавать новые номера, но не восстанавливают старые заказы.

## DNS и доступ с компьютера

A-записи `snowbrick.ru` и `www.snowbrick.ru` направлены на `194.58.102.218`; NS — `ns1.reg.ru` и `ns2.reg.ru`. Google и Cloudflare DNS через HTTPS показывают правильный адрес; GitHub Actions и VPS успешно проверяют сайт по домену.

На исходном Windows-компьютере около 21:36 МСК обычный DNS всё ещё возвращал прежний `194.58.112.174`, даже после `ipconfig /flushdns`. Поэтому встроенный браузер получал `ERR_CONNECTION_CLOSED`. С того же компьютера запрос HTTPS с явным правильным IP (`curl --resolve`) успешно вернул 200 для `/login`, с проверкой сертификата. Это отдельная проблема локального DNS-кэша/маршрута VPN, а не отказ развёрнутого сайта. Системный hosts и настройки VPN не менялись.

Отдельная DNS-панель из письма VPS (`dnsadmin.hosting.reg.ru`, NS5/NS6) не используется для этой зоны. Присланный для неё пароль ранее не подошёл и как рабочий секрет не сохранён. Это не мешает текущему домену.

## Продолжение работы

1. При следующих изменениях выполнить `node --test`, затем push; для обновления VPS отдельно запустить `Deploy production` вручную.
2. При получении следующего реального события СДЭК проверить `connection.lastWebhookAt` после входа. Не удалять прежнюю подписку или сервер без решения владельца.
3. Настроить регулярные проверяемые резервные копии `/var/lib/amo`, `/etc/amo.env` и root-файла реквизитов; автоматический backup приложения пока не реализован.
4. При необходимости настроить отдельного пользователя развёртывания и SSH-ключ вместо root-пароля.

История прежнего развёртывания: [LEGACY-CLOUD4BOX.md](LEGACY-CLOUD4BOX.md). Обычный push обновляет GitHub и запускает тесты, но сам по себе не устанавливает новую версию на VPS.
