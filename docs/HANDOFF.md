Общего метода перечисления всего исторического архива в используемом API нет. Эти 20 заказов — известная выборка, полнота архива не подтверждена. Вебхуки позволяют узнавать новые номера, но не восстанавливают старые заказы.

## DNS и доступ с компьютера

A-записи `snowbrick.ru` и `www.snowbrick.ru` направлены на `194.58.102.218`; NS — `ns1.reg.ru` и `ns2.reg.ru`. Google и Cloudflare DNS через HTTPS показывают правильный адрес; GitHub Actions и VPS успешно проверяют сайт по домену.

На исходном Windows-компьютере около 21:36 МСК обычный DNS всё ещё возвращал прежний `194.58.112.174`, даже после `ipconfig /flushdns`. Поэтому встроенный браузер получал `ERR_CONNECTION_CLOSED`. С того же компьютера запрос HTTPS с явным правильным IP (`curl --resolve`) успешно вернул 200 для `/login`, с проверкой сертификата. Это отдельная проблема локального DNS-кэша/маршрута VPN, а не отказ развёрнутого сайта. На момент этой проверки hosts и настройки VPN не менялись; последующее исправление описано ниже.

Отдельная DNS-панель из письма VPS (`dnsadmin.hosting.reg.ru`, NS5/NS6) не используется для этой зоны. Присланный для неё пароль ранее не подошёл и как рабочий секрет не сохранён. Это не мешает текущему домену.

## Продолжение работы

1. При следующих изменениях выполнить `node --test`, затем push; для обновления VPS отдельно запустить `Deploy production` вручную.
2. При получении следующего реального события СДЭК проверить `connection.lastWebhookAt` после входа. Не удалять прежнюю подписку или сервер без решения владельца.
3. Настроить регулярные проверяемые резервные копии `/var/lib/amo`, `/etc/amo.env` и root-файла реквизитов; автоматический backup приложения пока не реализован.
4. При необходимости настроить отдельного пользователя развёртывания и SSH-ключ вместо root-пароля.

История прежнего развёртывания: [LEGACY-CLOUD4BOX.md](LEGACY-CLOUD4BOX.md). Обычный push обновляет GitHub и запускает тесты, но сам по себе не устанавливает новую версию на VPS.

## Исправление доступа на исходном компьютере — 22:00 МСК

Пользователь открывал локальный файл `public/login.html` через `file:///`, поэтому эта копия формы не отправляла запрос входа на сервер. Правильный адрес — https://snowbrick.ru/login. Выданные реквизиты дополнительно проверены: сервер успешно принимает их; пароль не менялся.

С разрешения пользователя в системный hosts Windows добавлена только запись `194.58.102.218 snowbrick.ru www.snowbrick.ru` с комментарием `# Snowbrick VPS access - added by Codex`. Она устраняет влияние старого DNS-ответа для этих двух имён. Настройки VPN не менялись. После изменения обычный HTTPS-запрос с компьютера вернул 200, а в Edge выполнен вход на настоящем домене: пользователь admin, 20 заказов, API СДЭК подключён.

Резервная копия исходного hosts сохранена локально в `data/hosts-before-snowbrick-20260917-220002.backup`; скрипт исправления — `data/fix-snowbrick-dns.ps1`, результат — `data/snowbrick-dns-result.json`. Эти локальные файлы исключены из Git. Для отмены на этом компьютере запустить скрипт с `-Undo` от администратора либо удалить только указанную запись и её комментарий из hosts, затем очистить DNS-кэш. При будущем изменении IP сервера эту локальную запись нужно обновить или удалить.
