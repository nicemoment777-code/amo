# Передача проекта — 17 сентября 2026

## Что готово

Репозиторий: https://github.com/nicemoment777-code/amo, основная ветка `main`.

Веб-приложение на Node.js без внешних зависимостей. Локальный адрес: `http://127.0.0.1:3080/`. Есть поиск, фильтры, карточки заказов, полный ответ API и сводка товаров по цвету и количеству. Завершённые отправления определяются по статусу вручения; возвраты нужно анализировать отдельно.

На исходном компьютере сохранено 20 заказов, все 20 успешно обновлялись через API СДЭК. Локальные данные в `data/orders.json` не входят в Git. Номера для повторной загрузки сохранены отдельно в секрете `CDEK_ORDER_NUMBERS`; это список известной выборки, а не гарантия полного архива аккаунта. Ответы API содержат персональные данные получателей, поэтому не прикладывать их к публичным Actions artifacts или коммитам.

Известные номера обновляются при запуске и каждые 15 минут. Очередь сохраняется, ошибки повторяются раз в минуту. Исторические данные кабинета сохраняются в `cabinetSnapshot`.

Приёмник `POST /webhooks/cdek/<секрет>` реализован и проверяется тестами. Он ставит номер в очередь и перечитывает заказ через API. Публичного адреса и подписки СДЭК пока нет.

## Что осталось

1. Восстановить SSH-доступ к VPS. С Windows и Git Bash последний результат: TCP-соединение устанавливается, но SSH-приветствие не приходит до тайм-аута. До ввода пароля дело не дошло. Это не подтверждает ни исправность SSH, ни ошибку пароля. Сервер не изменялся.
2. Разместить приложение как постоянную службу на VPS, перенести данные защищённым способом или повторно загрузить известные номера.
3. Настроить домен, HTTPS и закрытый доступ к интерфейсу. Текущий сервер проверяет Host и Origin только для localhost; публикация через домен потребует явной настройки этих проверок и аутентификации.
4. Настроить публичный webhook endpoint, затем проверить существующие подписки СДЭК и добавить `ORDER_STATUS`, не удаляя чужие подписки.
5. Проверить получение нового номера, обновление карточки и восстановление службы после перезагрузки.

Разработка может идти в Codex Cloud, проверки — в GitHub Actions. Постоянную синхронизацию и вебхуки должен обслуживать VPS, а не временный контейнер задачи.
